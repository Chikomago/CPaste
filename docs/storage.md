# 图片资源存储

设计参考 EcoPaste：原图、缩略图和应用图标独立落盘，数据库只存引用和元信息。现有开发版、正式版仍共用 `app.cpaste.desktop` 数据目录。

```text
app.cpaste.desktop/
├── cpaste.db
├── resources/
│   ├── clipboard-images/
│   │   ├── origin/<哈希前两位>/<哈希>.<格式>
│   │   └── thumbnails/<哈希前两位>/<哈希>.png
│   └── app-icons/<哈希>.png
└── cpaste-before-resources.cpaste  # 首次迁移前的安全备份
```

- 原图按原始编码字节计算 SHA-256，相同内容共用文件。压缩或转换后的 JPEG 等格式保留原始编码。
- 缩略图首次显示时生成，最长边 300px，不放大小图；以 PNG 缓存到磁盘。界面通过 Tauri 资源协议加载文件路径，不经 Base64 IPC。
- 应用图标按内容缓存，来源应用更新后重新提取；应用卸载后仍可使用已有图标。
- 删除、自动清理和图片处理后清理无引用资源，共享文件仅在最后一个引用删除后移除。启动时重试资源清理。
- 存储用量包含数据库及其 WAL/SHM 和 `resources`；独立安全备份与 WebKit 网络缓存不计入历史存储用量。

## 迁移与备份

首次启动新版本会先创建 `cpaste-before-resources.cpaste`，再将数据库原图写入资源文件，事务提交后清除旧 BLOB 和旧缩略图缓存，并收缩数据库。迁移失败时旧记录不提交更改。安全备份会额外占用磁盘，不自动删除。

`.cpaste` 仍是单文件备份：导出时把原图写入备份数据库，缩略图和图标缓存不导出。恢复先在临时数据库中校验并生成资源，成功后才替换当前数据；旧版备份仍可恢复。

不要单独移动或删除 `resources`：数据库中的图片引用依赖这些文件。跨设备迁移应使用应用内备份与恢复。

## 占用明细与清理

“存储”按历史数据、图片原图、缩略图、应用图标显示占用，合计与左下角存储用量一致。临时预览、网页缓存和迁移前备份不提供统计及清理入口。

- 历史数据提供“整理”和“清空所有记录”；整理保留记录与设置，清空记录须确认。
- 清理原图会删除全部图片记录，包含置顶和收藏，需确认。
- 缩略图和应用图标缓存清理后按需重建；已卸载应用的图标可能无法重建。
